# Contribution Policy

## Before proposing a change

Do not add personal case details, beneficiary names, immigration status, live locations, identity documents, payment credentials, private keys, seed phrases, full bank details, or unpublished operational locations.

Listing changes must cite a public source and remain `unverified` and `publishable: false` until the required human attestations exist. Automated extraction and translation can create review candidates but cannot approve publication.

Sponsor work must remain structurally separate from service ranking, verification, and beneficiary-facing code. Activity work is deny-by-default and may not create a job marketplace or publish a paid offer without the required accountable operator and sector gates.

## Required checks

Run `npm run build`. A change is not ready if data validation, prohibited-feature tests, sponsor-boundary tests, or the frontend build fails.

## Review priority

Review emergency information first, then healthcare, accommodation, food and water, followed by all other services. Record the source, reviewer role, decision, and expiry without committing private evidence.
